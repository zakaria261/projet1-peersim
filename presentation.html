Dispatcher central

processEvent() — switch sur msg.type 
switch (msg.type) {
  case JOIN_REQUEST  → handleJoinRequest()
  case JOIN_ACCEPTED → mettre à jour pred/succ
  case LEAVE_NOTIFY  → leaveNetwork()
  case UPDATE_PRED   → this.pred = msg.content
  case UPDATE_SUCC   → this.succ = msg.content
  case SEND/PUT/GET  → handleRouting()
  case STORE_REPLICA → replicaStore.put(...)
  case GET_REPLY     → afficher le résultat
}

Join — insertion step-by-step

Nouveau nœud N

JOIN_REQUEST → Node 0
→
pred.id < N.id < succ.id ?

JOIN_ACCEPTED
handleJoinRequest() 
// Cas normal
if (this.id < mySucc.id) {
  inBetween = newId > this.id
           && newId < mySucc.id;
}
// Wraparound (ex: pred=90, succ=10)
else if (this.id > mySucc.id) {
  inBetween = newId > this.id
           || newId < mySucc.id;
}

if (inBetween) {
  this.succ = newNode;
  send(JOIN_ACCEPTED, [me, oldSucc], newNode);
  send(UPDATE_PRED,    newNode,      oldSucc);
} else {
  forward(msg, this.succ); // hop suivant
}

Anneau reformé
leaveNetwork() 
public void leaveNetwork(Node me, int pid) {
  // pred.succ ← mon successeur
  send(UPDATE_SUCC, this.succ, this.pred);
  // succ.pred ← mon prédécesseur
  send(UPDATE_PRED, this.pred, this.succ);

  this.pred = null;
  this.succ = null;
}
RingObserver parcourt l'anneau toutes les 200 unités de temps et détecte les succ null (boucle brisée) ou les boucles infinies (compteur > 2×N).

Étape 4

Routage avancé — Piggybacking

Le problème

Le routage de proche en proche est en O(N) — prohibitif à grande échelle.

Approche retenue : Piggybacking ✓

À chaque message reçu, on extrait l'expéditeur et on l'ajoute à une liste longLinks (max 5, similaire à une Finger Table).

processEvent() — apprentissage passif 
// Sur CHAQUE message entrant
if (msg.sender != null
  && msg.sender != node
  && !longLinks.contains(msg.sender)
  && longLinks.size() < 5) {
    longLinks.add(msg.sender);
}
handleRouting() — sélection du meilleur saut 
Node best = this.succ;
long bestDist = dist(this.id, targetId);

for (Node link : longLinks) {
  long d = dist(link.id, targetId);
  if (d < bestDist) {
    bestDist = d; best = link;
  }
}
// Tag console pour prouver le raccourci
log(best == succ ? "[FORWARD]" : "[SHORTCUT]");
EDSimulator.add(1, msg, best, pid);

Approche rejetée : Vue globale ("tricher")

✗ Network.get(random)

Piocher des nœuds depuis la classe globale Network brise l'aspect distribué — un vrai nœud n'a pas de vue globale du réseau.

Impact sur les performances

O(N)
Anneau simple
O(log N)
Avec piggybacking
Note : La distance utilise |id1−id2|. La version exacte serait (id2−id1) mod MAX pour respecter la circularité.
